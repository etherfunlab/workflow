# engineering

出自心法：代码为王、权威唯一、留心接口。

## 这是什么

十条工程姿态，写进你仓里的主规则文件（AGENTS.md，没有的话是 CLAUDE.md），agent 每次会话都会读到。

## 为什么

agent 写代码很快，所以也很快就能堆出过早的抽象、两处存放的同一个事实、没人要的接口。这几条规矩管的是 agent 自己不会主动收手的地方：该少写的时候少写，该复用的时候先找，判断线上状态时看正在运行的那一版。

## 规矩

- **KISS。** 三处相似的代码好过一个早产的抽象。不为还没出现的需求预留扩展点，不为内部可信的代码添加防御性校验。
- **一个事实只有一个权威来源**（出自权威唯一）。数值、状态、判定条件各钉一处，其余一律派生：视图、计算、join。宁可多一次派生查询，也不加一列冗余。
- **schema 以迁移文件为准，接口以代码为准**（出自代码为王）。文档里不维护它们的副本，链接到源头。
- **加接口之前先找能复用的**（出自留心接口）。拿不准一段逻辑该放在前端中间件还是后端接口时，先问人再写。
- **调参只求把错误率降下来，不追求清零。** 逼近零就是在拟合这一批语料的噪声，换一批就崩。指标持平不算待办。
- **判断线上状态看发布，不看分支。** 查部署或发布列表才知道线上运行的是哪一版；部署之前先想好回滚路径。
- **回归对比看失败用例的名字集合，不看失败数量。** 失败数相同，可能是新回归恰好和一个消失的 flaky 用例抵消了。基线在单独的 worktree 里 checkout，执行同一条命令。
- **契约先行**（出自代码为王）。先声明接口契约（schema、DTO、路由）再写实现；生成出来的 API 文档是产物，不是真相源。
- **外键建表时就定**（出自权威唯一）。指向别表的 id 列，在建它的那次迁移里就加外键；可空性与 ON DELETE 是同一个决定：可空配 SET NULL，非空只能 CASCADE。每个外键列都要有索引。上级 id 能唯一确定的事实不存第二份。
- **先放再收。** 尺度、能力、权限先放开跑，看清真实上限和实际用法，并让放开的那段留下读数。收的是门槛——条件、档位、冷却、代价——不是把能力拔掉。没有实测过的兜底，不提前收紧。（这条是我们的主张，不算公认实践。）

完整规则在 [`agent/rules/engineering.md`](agent/rules/engineering.md)。

## 装进你仓里的是什么

主规则文件（AGENTS.md，没有的话是 CLAUDE.md）里的一节 `## Engineering`。你仓里已经有同义的规则，ADOPT 就跳过那一条；有冲突的，ADOPT 会把两条并排给你看，由你选。
