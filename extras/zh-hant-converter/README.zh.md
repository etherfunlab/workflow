# zh-hant-converter

补充：不出自心法，给深港团队用。

## 这是什么

把简体中文转成繁体中文的 skill。繁体从不单独写，一律从简体源头转过来。分两种模式，用之前先判断这次是哪一种。

## 为什么

对内和对外的读者不一样。团队内部的文档主要给 agent 和工程师读：简中的技术语料多，名词有国家规范，港台译名却各有各的叫法，agent 读简中效率更高，所以对内只转字形，技术词按简中原词逐字转。产品的繁中页面是给用户读的，要用当地用户熟悉的词，所以对外还要换词汇。

## 怎么用

说「转繁」「同步繁体」或「convert to zh-Hant」。

| 模式 | 用在哪 | 怎么转 |
|---|---|---|
| 对内 | 团队内部文档，agent 干活时读的东西 | 先写简体，再 `opencc -c s2hk`；技术词照简中原词直转（软件 → 軟件，数据 → 數據） |
| 对外 | 产品的繁中页面或 locale 文件 | 先转字形（香港用 `s2hk`，台湾用 `s2twp`，后者已顺带换掉一部分词），再把大陆词换成当地产品界面的惯用词（台湾的例子：软件 → 軟體，数据 → 資料） |

两种模式共用同一套纪律：

- 只转这次改动涉及的内容，只动值和正文，key、结构、顺序都不动。
- 白名单逐字保留：`{token}` 这类占位符、链接引用、品牌词、专有名词、URL、email、代码。
- 标点保持全角，「——」原样。
- 不顺手润稿。腔调有问题，回简体源头改，再重新转。
- 不改简体源文件，不碰其他语言。
- 转完跑你配置的校验命令，再看 diff，确认只有目标内容变了。

## 装进你仓里的是什么

skill `zh-hant-converter`，装在你选的 skills 目录。ADOPT 会问四件事：简体源文件在哪、繁体输出在哪、不转换的品牌词、校验命令（没有可以不填）。

## 依赖

[OpenCC](https://github.com/BYVoid/OpenCC)（macOS：`brew install opencc`）、`git`。
